# 智芽真实课程学习计划与 AI 排课设计

日期：2026-10-25
状态：已获用户确认，等待规格复核后实施

## 1. 目标

把“我的—成长安排”从固定演示内容改造成与当前账号、当前年级、真实知识课程和测试关卡联动的学习计划系统。学生既能自己安排未来 7 天的学习，也能使用与 AI 伙伴相同的 DeepSeek 服务生成完整建议。AI 建议只能在学生预览并确认后写入计划。

本次改造必须满足：

- 只展示当前具体年级所属年级段的真实知识课程和测试关卡。
- 未完成内容优先；已完成内容仍可选择，并明确标记为“复习”。
- 学生可以添加、删除、排序和修改日期、时间、预计时长。
- AI 根据真实课程、完成进度、现有错题和学生可用时间生成未来 7 天计划。
- AI 计划先预览、可编辑，学生确认后才写入。
- 计划项可直接进入对应知识课程或测试关卡。
- 学习完成状态自动回写计划，并沿用现有积分、勋章和成长画像逻辑。
- 逾期未完成项目标记为“待调整”，AI 只能提出改期建议，不能自动改期。
- DeepSeek 不可用时保留已有计划和手动编辑能力，并提供本地基础建议。

## 2. 非目标

- 本阶段不建设真实云端账号同步，计划继续跟随当前账号保存在本地。
- 不改变现有知识课程、测试题目、积分数额、勋章获得规则或成长画像算法。
- 不允许 AI 创造项目中不存在的课程、测试或奖励。
- 不引入监护人审批；采用计划属于中风险操作，使用“预览—学生屏幕确认”流程。
- 不以 AI 对话内容作为成长画像数据。

## 3. 已确认的产品规则

1. 内容范围采用当前年级段的全部知识和测试；未完成内容优先，已完成内容可作为复习。
2. 页面提供“自己安排”和“AI 帮我安排”两个入口。
3. AI 生成未来 7 天计划，学生先设置每天可学习的时间段和大约时长。
4. AI 建议展示完整预览、安排理由和变更内容，确认后才落库。
5. 完成知识或测试后，计划自动显示完成，并同步现有积分、勋章和成长画像；逾期项目需确认后改期。

## 4. 现状与改造边界

当前 `src/features/profile/plan.ts` 保存三条固定任务；`GrowthSection.tsx` 使用固定“图片识别小探索”和轮换的静态 AI 文案；`LearningSchedulePage.tsx` 只能对三条任务前后调整 30 分钟；`CalendarPage.tsx` 也读取同一静态数组。

课程真相源已经存在于 `courseCatalog.ts`，学习进度存在 `AppState.learningProgress`。本次将新增独立的计划领域模块，由成长卡片、7 天安排页和月历共同读取；课程完成状态仍以 `learningProgress` 为唯一真相源，不在计划中重复维护一份容易失真的完成状态。

## 5. 数据模型

在账号级 `AppState` 中新增：

```ts
type LearningPlanTask = {
  id: string
  grade: PrimaryGrade
  partId: CoursePartId
  kind: 'knowledge' | 'test'
  title: string
  date: string       // YYYY-MM-DD，本地日期
  time: string       // HH:mm
  minutes: number    // 5—90
  order: number
  source: 'student' | 'ai' | 'fallback'
  review: boolean
  createdAt: string
  updatedAt: string
}

type DailyAvailability = {
  date: string
  enabled: boolean
  startTime: string
  endTime: string
  maxMinutes: number
}

type LearningPlanState = {
  tasks: LearningPlanTask[]
  availability: DailyAvailability[]
  lastAiSuggestionAt: string | null
}
```

约束：

- `partId` 必须属于当前年级段真实课程。
- 测试可以进入计划，但若对应知识尚未完成，界面提示“先学知识”，启动时先进入知识内容。
- `review` 由当前进度推导并在写入时固化为展示提示；完成状态始终实时从 `learningProgress` 推导。
- 删除任务只删除计划，不影响学习进度和奖励。
- 状态版本升级并提供迁移。已有账号首次升级时生成适量的真实示例计划，不保留三条旧虚构任务。

## 6. 页面设计

### 6.1 成长安排卡片

- 显示未来最近一条未完成计划。
- 顶部展示“知识”或“测试”标签，以及当前年级标签。
- 主标题使用真实课程或测试名称。
- 显示日期、时间、预计时长和后续项目数量。
- 已完成复习项目显示“复习”，逾期项目显示“待调整”。
- 主操作为“开始学习”；次操作为“调整安排”；底部操作改为“AI 帮我安排”。
- 没有计划时显示温和空状态，并提供“自己安排”和“AI 帮我安排”，不制造焦虑。

### 6.2 未来 7 天学习安排页

- 顶部为连续 7 天日期条，可快速切换日期。
- 下方按天分组显示计划；每项带类型、标题、时间、时长、状态和拖动手柄。
- “添加学习内容”打开内容选择器，分为“知识”和“测试”，来源只取当前课程包。
- 学生可删除、拖动排序、修改日期、时间和 5—90 分钟时长。
- 已完成内容可选择，但在选择器和计划中标记“复习”。
- 所有手动修改即时保存到当前账号本地状态。
- 点击计划项或“开始”按钮进入精确内容；测试未解锁时先进入对应知识页。

### 6.3 AI 帮我安排

流程分三步：

1. **设置时间**：学生为未来 7 天启用或停用日期，填写可学习时段和最多可用分钟数。
2. **生成建议**：服务端依据真实课程清单、完成进度、错题摘要和可用时间生成结构化建议。
3. **预览确认**：按天展示建议任务、安排理由、总时长和与现有计划的变化。学生可删除、换时间、调整顺序、逐项采用或一键采用；只有“确认采用”会写入。

AI 建议使用鼓励性、具体、可操作的表达，不使用“落后”“薄弱”“必须完成”等压力性表述。每天安排不超过学生填写的时间容量，并在知识与测试之间保留合理顺序。

### 6.4 学习日历

- 月历继续展示有安排日期，但数据改为账号计划。
- 选中日期后显示真实计划、类型、时间、时长和实时完成状态。
- 可从当天列表直接进入学习或跳转到 7 天安排页编辑。

## 7. AI 服务设计

在现有 `server/ai-proxy.mjs` 增加：

```text
POST /api/companion/schedule
```

接口复用现有 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL` 和仅服务端读取密钥的方式。浏览器不保存、返回或记录密钥。

请求包括：

- 当前具体年级和年级段；
- 未来 7 天可用时间；
- 真实课程与测试 ID、标题、建议时长；
- 知识完成和测试通过情况；
- 当前计划；
- 当前账号已有的错题摘要（没有则传空数组）。

响应采用结构化 JSON，包含每天的任务、简短理由和整周建议。服务端执行二次校验：

- 丢弃不存在或不属于当前年级段的 `partId`；
- 丢弃未知 `kind`；
- 将日期限制在未来 7 天；
- 将时间限制在学生填写的可用时段；
- 将单项时长限制在 5—90 分钟，并限制每日总时长；
- 过滤重复任务和不适龄文字；
- 确保未完成知识在对应测试之前。

若上游失败、超时、返回非 JSON 或校验后没有有效任务，接口返回可识别错误。客户端不覆盖原计划，转而生成同一课程清单上的本地基础建议，并明确提示“AI 暂时没连上，先给你一份可以继续修改的基础安排”。

## 8. 本地基础排课规则

1. 按“未完成知识 → 已学知识对应的未完成测试 → 复习”排序。
2. 从学生启用的日期和最早可用时段开始放置。
3. 单项默认 15 分钟；若课程已有合适时长则使用课程时长。
4. 不超过每天 `maxMinutes`。
5. 同一 `partId` 的知识排在测试之前，至少不晚于测试。
6. 无可用日期时不生成任务，并引导学生先设置时间。

## 9. 导航与奖励联动

- 知识计划项打开对应 `CourseContentPage`。
- 已解锁测试计划项打开对应 `QuizModal` 或测试关卡。
- 未解锁测试点击后说明原因并打开对应知识。
- `completeKnowledge` 和 `passTest` 继续负责写入进度及触发积分、勋章、年级段奖励。
- 计划页面通过进度实时推导“已完成”，不再次发放奖励，避免重复积分。
- 逾期未完成任务只标记“待调整”；AI 生成改期预览，学生确认后改变日期。

## 10. 安全、隐私与错误处理

- 请求不包含手机号、邮箱、密码、监护人手机号、AI 长期对话或无关个人资料。
- 错题只发送题目主题和知识点摘要，不发送学生自由输入的敏感内容。
- 服务端沿用儿童内容规范，并为排课增加负担控制和温和措辞规则。
- 请求期间允许取消，重复点击不会发出并行写入。
- AI 建议保存在临时预览状态；刷新或关闭预览不会修改正式计划。
- 本地存储失败时提示学生重试，不显示“已保存”。

## 11. 测试与验收

### 单元测试

- 当前具体年级映射到正确课程包。
- 真实知识和测试生成可选项，未完成优先、完成内容标记复习。
- 计划模型迁移、规范化、账号隔离和日期边界正确。
- 完成状态由 `learningProgress` 推导，删除计划不影响进度。
- 本地排课遵守可用时间、每日时长和知识先于测试。
- AI 响应校验会拒绝未知课程、越界日期、非法时长和重复任务。

### 组件与集成测试

- 成长卡片显示真实下一项，而非固定演示标题。
- 学生可以添加、编辑、排序、删除并在刷新后恢复计划。
- AI 预览未确认时不会修改计划；确认后 7 天安排和日历同步。
- 点击知识和测试任务进入精确内容；未解锁测试回到对应知识。
- 完成课程后计划显示完成，积分和勋章只发放一次。
- 逾期任务显示待调整，不会自动改期。
- AI 接口不可用时已有计划不丢失，手动安排和本地建议可用。

### 完整验证

- 运行现有 `npm run test:all`。
- 运行新增学习计划与 AI 接口测试。
- 运行 `npm run build`。
- 在 1—2、3—4、5—6 三个年级段分别手动检查成长卡片、7 天安排、AI 预览、月历和精确跳转。
