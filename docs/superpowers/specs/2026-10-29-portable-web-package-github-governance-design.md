## 1. 目标

在不移除现有功能、不破坏学习进度机制和作品链路的前提下，完成以下交付：

1. 安全清理和优化本地项目，删除可证明无用的代码、缓存、构建产物、重复文件与旧 worktree 副本。
2. 生成一个包含完整项目、便携运行环境、启动脚本、本地 AI 配置和统一比赛演示数据的 Windows ZIP。
3. 将 ZIP 放到 `E:\智芽\运行文件\智芽-Web完整演示包.zip`，同时保留现有 `智芽.apk`。
4. 将不含任何真实密钥的最新源码同步到 GitHub `main`。
5. 把公开仓库调整为比赛展示与开发维护兼顾的项目，并配置非商业许可证、分支保护、安全功能和协作权限。

- GitHub 仓库继续保持公开。
- 项目采用 `PolyForm Noncommercial 1.0.0`，替换当前允许商业使用的 MIT License。
- ZIP 使用本地真实 `.env` 和 API Key，以保持与当前电脑演示相同的本地代理链路。
- 真实密钥不得进入 Git 提交、GitHub、日志、README、校验文件或命令输出。
- ZIP 仅用于可信设备和可信人员；拥有 ZIP 的人理论上可以提取其中的 Key。
- ZIP 为 Windows 10/11 完整免环境版，内置便携 Node.js、Python 和项目依赖。
- 统一演示账号继续使用 `123 / 123`，启动后加载稳定的比赛演示数据，不复制当前浏览器个人缓存。

- `main` 禁止强制推送和删除；仓库所有者可直接推送，其他协作者必须通过 Pull Request 和自动测试。
- GitHub 首页采用“比赛展示 + 开发文档”双层结构。
- 启动时使用固定端口；自动结束本交付包残留的旧进程，外部占用进程必须人工确认，系统服务不得被结束。

## 3. 交付包架构

ZIP 解压后形成单一根目录：

```text
智芽-Web完整演示包/
├─ 启动.cmd
├─ launcher/
│  ├─ start.ps1
│  ├─ health-check.ps1
│  └─ process-manager.ps1
├─ runtime/
│  ├─ node/
│  └─ python/
├─ project/
│  ├─ src/
│  ├─ public/
│  ├─ server/
│  ├─ apps/
│  ├─ packages/
│  ├─ scripts/
│  ├─ docs/
│  ├─ templates/
│  ├─ android/
│  ├─ node_modules/
│  ├─ package.json
│  └─ 其他必要配置
└─ data/
   └─ 统一比赛演示数据
```

交付包由白名单清单生成，不复制整个工作目录后再排除。白名单必须覆盖主应用、AI 代理、课程资源、作品资源、两个创作子应用、Android 源码、测试所需配置和运行依赖。以下内容不得进入 ZIP：`.git`、`.worktrees`、构建缓存、历史打包目录、验证截图、临时日志、浏览器用户目录、个人缓存和无关开发工具。

真实 `.env` 仅在最后的私有交付暂存阶段复制。打包脚本的通用清单、测试夹具和 GitHub 代码不得包含密钥值。

## 4. 启动与进程管理

`启动.cmd` 调用随包分发的 PowerShell 启动器。启动器不得依赖系统 PATH 中的 Node.js 或 Python，而是显式使用 `runtime/node` 和 `runtime/python`。

启动顺序：

1. 校验目录完整性、运行环境、配置文件和可写数据目录。
2. 检查固定端口 `5173`、`5191`、`5192`、`8766`、`8787`。
3. 对命令行路径属于当前解压目录的残留 Node/Python 进程自动结束。
4. 对其他进程占用显示进程名称、PID 和端口，要求用户确认；系统服务和受保护进程永不结束。
5. 同时启动智芽主应用、脑洞放映厅前端、创造模块、脑洞放映厅 Python 后端和 AI 代理。
6. 等待各服务健康检查通过，再打开 `http://127.0.0.1:5173/`。
7. 控制台持续显示简洁状态，不打印密钥、请求正文、音频、图片或隐私数据。
8. 关闭控制台或按退出快捷键时，仅终止本次启动器创建的进程树。

启动失败时保留控制台，显示可执行的中文诊断信息和日志位置，不自动循环重启，不静默退出。

## 5. 演示数据

ZIP 不携带当前浏览器的 localStorage、IndexedDB 或登录会话。应用首次启动时使用既有的幂等种子逻辑，为 `123 / 123` 创建统一演示状态，包括：

- 合理的三学段课程进度；
- 与课程和测试一致的积分、勋章、错题和学习记录；
- 公共作品、收藏、草稿和不同发布状态的作品；
- 默认 AI 伙伴及商城演示状态；
- 已导入且可正常打开的脑洞放映厅示例作品。

种子必须可重复启动且不重复插入。用户后续产生的数据写入解压目录内的可写数据区域或浏览器存储，不写入便携运行时目录。

## 6. 安全清理与代码优化

清理分三层执行：

### 6.1 可再生文件

删除并按需重建 `.data/`、`dist/`、`tsconfig.tsbuildinfo`、日志、旧暂存目录、Android/Gradle 构建缓存、重复依赖和其他明确的生成物。

### 6.2 旧 worktree

项目内部三个干净的旧 worktree 使用 Git worktree 管理命令移除。对应分支和提交保留；位于项目外的 Codex worktree 不因本任务被删除。

### 6.3 代码与资源

只删除同时满足以下条件的内容：

- 没有静态导入或入口引用；
- 没有被课程、作品、伙伴、Vite、脚本或运行时清单动态引用；
- 删除后 TypeScript、构建和全量测试仍通过；
- 真实启动和核心页面验证未发现功能缺失。

无法证明无用的课程图片、视频、模型、作品资源和动态路径一律保留。不得以文件体积大为唯一删除依据。

## 8. Git 同步策略

当前本地 `main` 比远端 `origin/main` 多 41 个提交，当前修复分支比远端 `main` 多 48 个提交。实施期间：

1. 在当前分支完成清理、打包基础设施、文档和测试。
2. 每个独立交付形成清晰提交。
3. 全量验证通过后，将本地 `main` 快进到当前分支，不压缩、不改写提交。
4. 推送 `main` 和必要的当前分支更新。
5. 配置仓库 ruleset 和安全选项。
6. 重新拉取并比较本地、远端提交，确保同步完成。

实施前和推送前都进行秘密扫描。若发现真实密钥曾进入提交历史，立即停止推送，报告受影响范围，并优先轮换密钥；未经单独确认不重写历史。
