# 智芽：创意游戏与作品中心联动设计

日期：2026-10-20  
状态：已完成需求讨论，待用户审阅规格

## 1. 目标

在不改变智芽首页“滚动资讯 + 精选 AI 创意游戏 + 成果展示”现有奶油白、浅桃粉、柔和立体画风的前提下：

1. 将“脑洞放映厅”和“创造模块”作为两个独立子应用嵌入智芽，分别占据精选游戏区第 1、2 个入口。
2. 智芽启动时同时启动两个子应用服务，但不自动打开；学生点击游戏卡片后，在智芽 APP 框内进入对应二级界面。
3. 统一重绘首页的 5 个精选游戏图标和 1 个“全部游戏”图标，使六个图标在材质、视角、光线、尺寸和留白上统一。
4. 将两个游戏的作品导出、外部 AI 作品上传、“我的作品”和“看看大家的新作品”连接成一条真实可操作的本地演示流程。
5. 删除现有所有写死的普通演示作品。公开作品只来自两个游戏或学生主动上传的外部 AI 作品。

## 2. 已确认的产品决策

- 游戏集成方式：独立子应用 + 智芽内嵌二级页面，不跳新窗口。
- 游戏顺序：第 1 个“脑洞放映厅”，第 2 个“创造模块”；原第 3、4、5 个精选入口继续保留。
- 视觉范围：保留滚动资讯、游戏区和成果展示整段现有风格与信息密度，仅做必要的图标统一、作品真实化和二级页面适配。
- 作品导出：先保存到“我的作品”的“草稿”状态，学生手动发布后才进入公开作品流。
- 本地导出：两个游戏继续提供“保存到本地”。保存到智芽和保存到本地是两个明确动作。
- 互动：公开作品支持点赞、收藏和受限留言；留言经过内容检查。
- 外部上传：接受任意文件格式。可预览格式显示媒体预览，不可预览格式显示通用文件卡片。
- 数据阶段：首版只使用本地演示数据，不实现真实多用户服务端同步。

## 3. 总体方案

采用“仓库内微应用 + 受控消息桥 + 统一作品仓库”。

### 3.1 仓库结构

两个现有游戏源码迁入智芽仓库，保留各自独立入口、构建配置和运行环境：

```text
智芽-教育APP/
  apps/
    brain-film/          # 脑洞放映厅
    creative-module/     # 创造模块
  src/
    features/games/      # 智芽游戏入口、内嵌页面和消息桥
    features/works/      # 统一作品中心
```

迁移时不复制 `node_modules`、`dist`、临时缓存、密钥或本地环境文件。两个子应用仍是独立 React/Vite 应用，不把内部页面直接并入智芽组件树。

### 3.2 启动和构建

- 根目录 `npm run dev` 启动：智芽 Web、AI 代理、脑洞放映厅开发服务和创造模块开发服务。
- 两个游戏服务不会使用 `--open`，因此启动后不会弹出页面。
- 子应用使用固定且与现有 5173/5174 服务不冲突的开发端口；端口被占用时给出明确错误，不静默启用错误服务。
- 智芽开发环境通过配置读取两个游戏 URL。
- 生产构建时分别构建两个子应用，并作为智芽产物下的静态子路径发布；内嵌页不依赖电脑上的绝对路径。

### 3.3 APP 内二级游戏页

新增统一 `EmbeddedGamePage`：

- 顶部保留智芽风格的返回按钮、游戏名称和轻量状态提示。
- 主体用受控 `iframe` 承载子应用，保持子游戏自身布局和状态。
- 页面限制在智芽 APP 框内，不弹新标签页。
- 显示加载、启动失败和重试状态。
- 手机尺寸下自动隐藏不必要的外层留白，让子应用获得足够操作空间。
- 进入页面时才加载 iframe；未进入时服务虽已启动，但浏览器不请求游戏页面和高耗资源。

## 4. 首页游戏区和六个图标

### 4.1 卡片顺序

```text
脑洞放映厅 | 创造模块 | 分类挑战
机器判断局 | 创意拼搭站 | 全部游戏
```

第 1、2 个卡片进入真实二级游戏页；其余入口暂时沿用现有行为，避免本次任务扩张为另外三款游戏的开发。

### 4.2 图标视觉规范

六个图标全部重新生成或重绘，统一使用：

- 1:1 画布、透明背景；
- 柔和奶油白、浅桃粉、杏橙和少量彩虹高光；
- 精致软陶/磨砂玻璃般的轻立体材质；
- 轻微右上方主光、柔软投影、圆润边缘；
- 主体占画布约 72%，避免图标大小忽大忽小；
- 不在图标图片内放文字；
- 小尺寸下仍能一眼识别，不使用过细线条。

含义：

- 脑洞放映厅：故事画面、放映幕或胶片与灵感星光。
- 创造模块：可拼接模块、节点连线与创作火花。
- 分类挑战：被整理归类的彩色卡片/盒子。
- 机器判断局：友好机器人、判断标记与线索。
- 创意拼搭站：彩色积木、创意结构与小火花。
- 全部游戏：奖杯/合集入口，延续当前强调卡片的视觉重心。

滚动资讯、区块标题、卡片圆角和成果展示继续沿用现有画风，不进行大面积重排。

## 5. 统一作品数据模型

新增本地作品仓库，替换 `homeData.ts` 和 `WorksManagePage.tsx` 中写死的作品数组。

```ts
type WorkSource = 'brain-film' | 'creative-module' | 'external-upload'
type WorkStatus = 'draft' | 'reviewing' | 'published' | 'private'

interface WorkRecord {
  id: string
  ownerId: string
  source: WorkSource
  title: string
  description: string
  aiTools: string[]
  status: WorkStatus
  assetId: string
  fileName: string
  mimeType: string
  byteSize: number
  previewKind: 'image' | 'video' | 'audio' | 'text' | 'pdf' | 'generic'
  createdAt: string
  updatedAt: string
  publishedAt?: string
  likes: number
  favorites: number
  comments: WorkComment[]
}
```

- 元数据和二进制文件使用 IndexedDB 保存，避免图片、视频塞入容量很小的 `localStorage`。
- 数据按当前本地演示账号隔离。
- IndexedDB 配额不足或文件读取失败时保留表单内容，显示明确提示，不生成损坏作品。
- 为后续服务端同步定义仓库接口；页面只依赖接口，不直接操作 IndexedDB。

## 6. 子应用作品桥

智芽与两个 iframe 使用版本化 `postMessage` 协议通信：

```text
子应用 -> zhiyA.work.save-draft.v1
智芽   -> zhiyA.work.saved.v1
智芽   -> zhiyA.work.save-failed.v1
```

消息包括来源、作品名称、介绍、文件名、MIME 类型和 `Blob`。智芽侧必须：

1. 校验 `event.origin` 是否为两个已配置游戏地址之一。
2. 校验消息类型、版本、来源和字段长度。
3. 将作品写入当前账号的草稿仓库。
4. 返回作品 ID 和保存结果，让游戏显示“已保存到智芽·我的作品”。

子应用不能直接修改智芽账号、积分、勋章、AI 伙伴状态或公开作品列表。

### 6.1 两个游戏中的动作

- “保存到智芽”：生成当前作品文件并发送给宿主，进入草稿。
- “保存到本地”：继续使用浏览器下载，不写入智芽作品仓库。
- 已保存后再次保存同一作品时更新原草稿，而不是无限生成重复条目；显式“另存为新作品”才创建新记录。

## 7. 我的作品

“我的作品”保留原有完整状态设计，但数据改为真实仓库：

- 全部
- 草稿
- 审核中
- 已发布
- 仅自己

作品卡片显示真实封面/文件类型、来源游戏、更新时间和状态。支持：

- 草稿：查看、继续编辑（可返回来源游戏）、修改名称和介绍、保存到本地、提交发布、删除。
- 审核中：查看、撤回为草稿。
- 已发布：查看互动数据、撤回为仅自己或草稿。
- 仅自己：查看、重新提交发布或删除。

所有旧的普通演示作品删除；仓库为空时显示友好空状态和“去创作/上传作品”入口。

## 8. 任意格式外部上传

“我的作品”增加“上传 AI 作品”：

1. 文件选择器不限制扩展名和 MIME 类型。
2. 学生填写作品名称、简短介绍和使用过的 AI 工具。
3. 上传后默认保存为草稿。
4. 图片、视频、音频、文本和 PDF 使用对应预览器。
5. 其他格式使用通用文件卡片，显示文件名、扩展名、大小和下载按钮；不会尝试执行文件。
6. “接受任意形式”指不因格式拒绝保存；仍受浏览器可用存储空间约束。

## 9. 发布、成果展示和互动

### 9.1 发布状态流

```text
draft -> reviewing -> published
          |              |
          v              v
        draft          private
```

- 学生点击发布后进入“审核中”。
- 首版本地演示执行文本规范检查和文件安全检查；媒体深度审核通过可替换的审核接口预留，界面不虚假宣称已经完成真实多模态审核。
- 后续接入真实审核服务时沿用相同状态，不重做页面。

### 9.2 首页和更多作品

- “看看大家的新作品”只查询 `published` 作品。
- 每天/每周/每年按发布时间窗口筛选，再按点赞、收藏和留言热度排序。
- 没有公开作品时显示与首页风格一致的空状态，不重新塞入虚假普通作品。
- “更多作品”展示完整已发布列表。

### 9.3 点赞、收藏和留言

- 点赞、收藏和留言都写回统一作品仓库，因此首页、详情页和“我的作品”数据一致。
- 留言限制长度，并先执行年龄适宜、礼貌表达和敏感内容检查。
- 不合适的留言不保存，给出委婉的改写提示。

## 10. 错误处理与可访问性

- 子游戏未启动：内嵌页显示重试和返回，不出现空白 iframe。
- 作品桥消息非法：忽略并记录开发日志，不向学生暴露技术细节。
- 文件太大或配额不足：提示释放空间或改用“保存到本地”。
- 预览不支持：仍可显示文件卡片和下载，不把“不支持预览”误判为文件损坏。
- 图标图片包含有意义的替代文本，游戏卡片可用键盘操作。
- 内嵌页返回按钮始终可见，并避免游戏内容被底部导航遮挡。

## 11. 测试与验收

### 11.1 自动测试

- 首页游戏顺序、标题、六个图标资源和点击导航。
- 根启动脚本会启动两个游戏且不附带 `--open`。
- 二级游戏页加载、返回、失败和重试。
- 消息桥的来源验证、字段验证、成功回执和失败回执。
- 游戏导出后只产生草稿，不直接进入公开流。
- 外部任意格式上传与可预览/不可预览分支。
- 草稿、审核中、已发布、仅自己状态转换。
- 首页、更多作品和我的作品共享同一记录。
- 点赞、收藏、留言联动与不当留言拦截。
- IndexedDB 配额错误与空状态。

### 11.2 手动验收

1. 启动智芽，一个命令同时启动三个前端和 AI 代理，且只打开智芽页面。
2. 首页整体画风与确认截图一致，六个图标视觉统一且含义清楚。
3. 点击前两个游戏均在 APP 框内打开，可正常返回。
4. 两个游戏保存到智芽后，“我的作品”立即出现草稿。
5. 保存到本地可正常下载，且不会重复创建智芽作品。
6. 草稿发布后经历审核状态，再出现在首页和更多作品中。
7. 点赞、收藏和留言在所有页面同步。
8. 任意格式文件可以保存；不支持预览的文件仍可识别和下载。

## 12. 非目标与后续

本次不实现：

- 真实跨设备账号同步和真正的多用户公共社区；
- 真实多模态媒体审核服务；
- 另外三款精选游戏的具体内容；
- 云端大文件存储与断点上传。

这些能力均通过作品仓库接口、审核接口和子应用桥保留升级位置。本次交付以本地演示完整可用、视觉一致、数据联动真实为标准。
