# 脑洞放映厅本机浏览器版设计

## 目标

让中小学生在本机浏览器中独立完成“抽卡—写剧本—画分镜—首映”的创作闭环。AI 生成由电脑上的 Python 服务转发；浏览器和任何前端产物均不含 API 密钥。

## 运行边界

- React/Vite 前端固定监听 `127.0.0.1:5174`。
- Python 后端固定监听 `127.0.0.1:8766`，并以 Vite 的 `/api` 代理为唯一开发期访问路径。
- 后端从项目根目录 `.env` 读取模型、密钥和可选的 `HTTPS_PROXY`；`.env` 不进入前端、不被静态托管，也不写入日志。
- 火山方舟请求在已配置且可连接的代理存在时走代理；智谱请求维持直连。
- 本项目仅面向本机浏览器演示，不部署云端、不修改 Android 壳、不把密钥写入 APK。

## AI 能力

后端公开相对路径的 JSON API：

| 创作行为 | 浏览器调用 | 后端模型配置 |
| --- | --- | --- |
| 把卡片变成简介、写剧本、润色分镜提示词 | `/api/synopsis`、`/api/story`、`/api/polish` | `ZHIPU_MODEL` |
| 生成单格分镜 | `/api/image` | `ARK_MODEL`、`ARK_SIZE` |
| 生成短片并轮询状态 | `/api/video`、`/api/video/:taskId` | `VIDEO_MODEL` |
| 生成配音、合成首映影片 | `/api/tts`、`/api/film` | `VOICE_MODEL`、`VOICE_VOICE`、`VOICE_SPEED` |

学生点击生成会立即请求模型，不出现每次调用的付费确认。服务端保留既有请求频率、单作品图片数量、配音字符数和每日影片数量上限，以防误触发大量调用。

## 儿童创作体验

- 顶部保留六步创作进度；当前步骤旁给出一条短引导和唯一主行动。
- 在剧本和分镜阶段明确提示“谁、在哪里、做什么”，使学生能独立补全 AI 所需信息。
- 生成中显示当前环节、可等待提示及不会丢失草稿的说明；失败后显示中文原因和“重试”或“使用本机方案”的下一步。
- 在首次进入创作和提交长文本时提示不输入真实姓名、学校、地址、联系方式或其他隐私；提示不阻断普通创作。
- AI 不可用时，剧本仍使用本地整理逻辑，分镜可使用程序化插画，首映可使用本机录制。

## 启动与可恢复性

`launch.ps1` 是浏览器本机版入口：它检查端口、启动或复用 8766 后端、等待 `/api/health` 成功，再启动/打开 5174 前端。两个服务的本地日志保存到临时目录，且不得包含密钥。

## 错误与安全

- `/api/config` 仅返回模型名、就绪状态、网络状态与限制，不返回任何密钥、代理值或授权头。
- 上游异常在后端归一化为适合学生理解的中文信息；日志中只保留简短模块名和状态，避免输出授权凭据。
- `.env`、数据库和服务端源文件不作为静态资源暴露。

## 验收

1. 在已配置本机 `.env` 和可用代理的情况下，浏览器显示六项 AI 能力的可用状态。
2. 浏览器通过 Vite 代理可取得 `/api/health` 和 `/api/config`；响应中不含密钥或代理值。
3. 生成失败时学生可看懂下一步，草稿仍保留，且可切换至离线替代方案。
4. `npm run test`、Python 单元测试、`npm run build` 与已有后端 API 冒烟测试均通过；冒烟测试不发起会计费的模型调用。
